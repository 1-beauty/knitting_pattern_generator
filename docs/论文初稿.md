# 面向横机针织动作色码图的语义驱动生成与结构感知视觉预览方法

*A Semantic-Driven Action Map Generation and Structure-Aware Visual Preview Method for Flat Knitting Pattern Design*

---

## 摘要

现有生成式人工智能方法已能够根据自然语言生成纺织纹样、服装纹理或色彩方案，但多数结果仍停留在普通视觉图像层面，缺少横机针织制造所需的动作语义和针法约束。横机组织色码图并非一般像素图：每一个色块都对应成圈、集圈、移针、劈针、空针或落布等具体工艺动作，动作之间还存在支撑、偏移、堆叠、边界闭合和张力过渡等制造约束。因此，从自然语言设计描述到可验证组织色码图的自动生成，不能简单套用“文本生成图片”的技术路线。

本文提出一种面向横机针织的语义驱动动作色码图生成与结构感知视觉预览方法。系统以用户自然语言设计描述为输入，首先借助大语言模型 API 完成基础语义抽取，并将抽取结果约束为可编辑的层次化结构计划（PatternPlan），显式表示外轮廓、边框、内部纹理、背景组织及其父子关系；随后基于十五色针织动作空间，将结构计划逐级编译为视觉目标、工艺实现方案、稀疏事件点和动作色码图，并通过动作合法性约束、工艺启发式约束、张力评分、层级裁剪和成组组织完整性检查完成自修复；最后通过第二阶段结构感知视觉预览模块生成针织效果图，形成从语义输入、动作组织生成到视觉预览验证的闭环。本文中的大语言模型仅承担自然语言到结构化字段的接口作用，生成结果由显式结构表示、工艺规则与后处理校验共同决定。

本文的主要贡献包括：第一，提出 PatternPlan 层次化中间表示，用于显式建模几何轮廓、纹理效果、区域角色和父子关系，将自然语言中的形状、纹理、层级和位置关系拆解为可编辑的结构单元；第二，构建面向十五色针织动作空间的约束生成与自修复机制，将针织工艺知识嵌入动作网格生成过程，消融实验显示自修复模块能够在无硬约束违例和无层级外溢的前提下，将局部张力评分由 0.104 降至 0.031；第三，设计结构感知视觉预览流程，基于条件流匹配从动作图生成针织效果图，在 50 张验证图上的接缝误差随 stage 递进持续下降（0.069→0.038）。

**关键词**：横机针织；组织色码图；语义驱动生成；工艺约束；结构感知视觉预览

## 1 引言

### 1.1 研究背景与问题

横机针织组织设计通常依赖专业人员逐格编辑色码、设置针法并检查结构合理性。该流程不仅要求设计者理解图案外观，还要求其掌握针床切换、线圈支撑、集圈堆叠、移针偏移和局部张力等工艺知识。对于普通设计师或非专业用户而言，即使能够清楚描述“圆形结构，内部波浪吊目，外部矩形边框，背景稀疏网眼”等设计意图，也难以直接将其转换为具有针织工艺逻辑的组织色码图。

近年来，文本到图像生成、扩散模型、GAN 和服装纹理迁移方法推动了 AI 辅助纺织设计的发展。ColorwAI 关注纺织色彩变体生成，FabricDiffusion 面向服装图像的高保真织物纹理迁移，相关工作说明生成式模型已能够提升纺织视觉设计效率。然而，这类方法生成的通常是 RGB 图像、纹理贴图或色彩方案，不能保证图像像素对应合法的针织动作。

同时，2024 年以来的可制造生成研究开始强调物理约束和功能约束的重要性。Shaping Realities 讨论了 3D 生成中的制造约束，Stylish and Functional 强调物理约束在生成式设计中的作用。这些研究表明，生成式设计正在从“外观看起来合理”转向“结构上能够制造”。横机针织场景中的约束更加细粒度：颜色不是装饰，而是动作编码；形状不是普通轮廓，而是由成圈、集圈、移针和劈针等动作组合形成的组织结构。

因此，本文关注的核心问题是：如何把自然语言设计描述自动转化为具有针织工艺逻辑、满足面向横机动作图的结构约束与工艺启发式约束、并可通过视觉预览流程验证的横机组织色码图。需要指出的是，本文当前研究范围存在以下明确边界：画布固定为 40×40 的内部动作网格；动作空间为 15 类内部动作编码，不生成完整机台指令；不处理多纱嘴路径规划；第二阶段为视觉预览而非物理力学仿真；当前支持的语义类别限于圆形、菱形、矩形、六边形等几何形状与波浪吊目、蜂巢、网眼、平针等基础纹理的组合。

### 1.2 现有方法的不足

现有相关方法在本文任务中主要存在三类不足。

第一，传统横机 CAD 工具能够表达复杂针法并支持组织检查，但其工作流主要依赖人工组织编辑，通常不提供从自然语言设计语义到组织色码图的自动生成能力。

第二，AI 纺织图案生成方法能够生成视觉上类似纺织物的图像，却缺少针织动作语义。对于横机针织制造而言，视觉相似性不足以代表可制造性。一个看起来像波浪、蜂巢或网眼的图案，如果没有合法的集圈、移针、支撑和边界关系，仍然无法稳定进入后续工艺验证流程。

第三，约束感知生成方法虽然强调物理或制造约束，但多数面向 3D 几何、工程结构或材料外观，尚未针对横机组织色码图中的动作空间、针床关系、区域纹理、张力过渡和视觉预览验证建立完整链路。

综合来看，现有方法要么生成视觉纹理但不具备工艺动作语义，要么能够表达针织动作但依赖人工逐格编辑；尚缺少一种能够把自然语言设计意图映射为层次化结构计划，并进一步编译为满足动作约束的横机色码图的方法。

### 1.3 本文思路

针对上述问题，本文将横机组织生成拆分为两个阶段。

第一阶段是语义驱动组织生成。系统不直接把文本生成为图片，而是先将自然语言解析为层次化结构计划，再将结构计划编译为动作色码图。该阶段的关键是把“圆形、菱形、矩形边框、波浪吊目、蜂巢纹理、稀疏网眼”等设计语义转换为具有父子关系、区域边界和工艺实现方式的结构单元。

第二阶段是结构感知视觉预览验证。系统以第一阶段生成的内部十五色动作图为条件输入，结合中心动作、邻域动作和物理工艺特征，生成针织效果图。该阶段为研究和设计迭代提供自动化视觉验证，使用户能够观察纹理连续性、边界闭合程度和区域层级是否清晰。

### 1.4 创新点

本文创新点可概括为以下三点。

**1. 语义输入：PatternPlan 层次化中间表示。** 本文提出 PatternPlan 作为面向横机组织生成的结构化中间表示，将用户描述中的图案语义拆解为 motif 单元，每个 motif 包含 motif_type（形状）、effect（纹理效果）、role（主体/边框/内部纹理/背景）、region（位置与尺寸）、params（周期、密度、方向和厚度）和 parent_id（父子层级）等字段。系统使用大语言模型 API 执行初始语义抽取，但不将其输出直接作为最终图案，而是通过 schema 约束、字段归一化和工艺规则校验将其转化为可解释、可修改的针织结构计划。当前实现支持圆形、菱形、矩形、六边形等基础形状与波浪吊目、蜂巢、网眼、平针等纹理的组合。

**2. 约束控制：十五色动作空间上的工艺规则生成与自修复。** 本文基于 Neural Inverse Knitting 数据集中的动作色块体系构建十五色针织动作空间，并为每类动作建立语义类别、针床属性、移针偏移、张力等级、弹性等级和稳定性等级。这些属性并非来自实测传感器数据，而是结合公开工艺资料和系统调试经验建立的工程分级，在本文中作为规则排序与风险评估的启发式先验。系统在事件规划、动作构建、后处理和输出前检查中嵌入 8 项动作合法性约束、6 项工艺启发式约束和成组组织完整性检查，使生成结果具有针织组织逻辑。消融实验表明，自修复模块能够在无硬约束违例和无层级外溢的前提下，将局部张力评分由 0.104 降至 0.031。

**3. 第二阶段结构感知视觉预览：动作图到针织效果图的闭环。** 本文将内部色码图作为条件输入，结合中心动作、3×3 邻域动作和工艺属性特征，通过条件流匹配生成针织效果图。该过程使系统能够在动作规则检查之外进一步观察织物表面的边界、纹理和层级表现。需要说明的是，该阶段是条件图像生成任务而非物理力学仿真，其输出可用于设计迭代和视觉检查，但不能替代真实织造验证。在 50 张验证图上的定量评估表明，接缝误差随 stage 递进持续下降（0.069→0.038）。

## 2 相关工作

### 2.1 横机 CAD 与针织组织编辑

传统横机 CAD 工具以专业打版师为主要用户，支持针法编辑、组织绘制、工艺参数设置和机台指令导出。以 Stoll M1 Plus 为代表的系统采用图形化界面，通过针法符号库、组织填充和花型编辑器实现复杂组织的逐步编辑，其工作流通常为：组织图绘制 → 针法图生成 → 机台指令校验 → 打样 → 人工调整。Shima Seiki SDS-ONE APEX 系列则进一步集成了 3D 虚拟试衣和织物仿真功能，能够在数字环境中预览织物的悬垂和纹理效果。近年来，部分商业 CAD 开始引入 AI 辅助功能，如自动花型推荐和颜色方案生成，但这些功能仍以视觉层面的纹样建议为主，不涉及动作色码图的自动生成。

这些工具能够细致表达复杂组织，但其核心工作流仍然依赖人工逐格编辑色码和设置针法。对于非专业用户而言，即使能够清楚描述“圆形结构，内部波浪吊目，背景稀疏网眼”等设计意图，也难以直接将其转换为具有针织工艺逻辑的组织色码图。本文方法关注语义生成与视觉预览环节，旨在降低从设计意图到组织色码图之间的建模门槛，并为后续与商业 CAD 中的组织编辑或针法映射提供中间表示基础。

### 2.2 AI 纺织图案与服装纹理生成

生成式人工智能在纺织视觉设计领域已取得显著进展。ColorwAI 将纺织色彩变体建模为风格迁移任务，利用 GAN 与扩散模型的解耦能力生成多种配色方案，但不涉及针织动作语义。FabricDiffusion 面向 3D 服装图像的高保真纹理迁移，通过扩散模型从服装图像中恢复可平铺织物纹理贴图，其输出为 RGB 图像而非动作网格。Knit-FLUX 基于扩散模型的低秩适应技术生成针织织物视觉图像，能够模拟不同组织的外观效果，但其输出仍为视觉图像层面，不直接对应可执行的针织动作指令。

在约束感知生成方面，KnitDiff 是最直接的竞品工作，将约束感知扩散模型应用于针织图案生成。KnitDiff 以图像或条件标签为输入，通过扩散模型生成针织图案图像，并通过集成工艺规则提升生成质量。然而，KnitDiff 的输入不包含自然语言，输出为 RGB 图像而非动作网格，不支持层次化结构规划，也未报告真实织造验证。与 KnitDiff 的关键区别在于：本文的输入为自然语言设计描述，输出为具有十五色动作语义的组织色码图，且包含层次化结构计划和工艺约束自修复机制。由于任务定义和输出表示的根本差异，KnitDiff 不适合直接作为数值基线进行定量对比。

deepKnit 基于 LSTM 序列模型从文本描述生成机台织造代码。需要明确的是，deepKnit 的输出为线性指令序列（一行行的织造命令），而非 2D 动作网格。它不处理图案层级、父子区域关系或视觉预览，主要关注指令序列的可执行性。本文的方法则关注 2D 动作色码图的区域结构和可编辑层次，通过 PatternPlan 显式表示几何轮廓、纹理效果、区域角色和父子关系，并支持视觉预览验证。两者在输出表示和结构建模能力上具有本质差异。

skCAD 提出了一种面向立体编织的 CAD 设计工具，支持自动图案生成与制造约束检查，但主要面向圆机而非横机场景。与上述工作不同，本文方法同时强调语义驱动的结构化生成、十五色动作空间的工艺约束和条件流匹配的视觉预览验证，形成从语义输入到可观察织物效果的完整闭环。

### 2.3 约束感知生成与可制造设计

随着生成模型进入制造场景，约束感知生成成为重要研究方向。Shaping Realities 讨论了 3D 生成中的制造约束，强调生成结果必须满足物理可实现性而非仅视觉合理性。Stylish and Functional 研究了受物理约束的引导插值方法，在潜在空间中施加结构约束以保持生成结果的功能性。在 CAD 领域，Generative AI meets CAD 探索了 LLM 与参数化 CAD 的结合，将大语言模型作为设计意图到 CAD 操作之间的接口，但其约束主要面向几何和装配关系。

本文继承这一问题意识，但约束对象从 3D 几何或工程结构转向横机针织动作色码图。横机场景的约束更加细粒度：不仅包括形状对称和边界完整，还包括线圈支撑关系（下方必须有动作支撑）、移针目标合法性（不超出画布且不冲突）、连续集圈上限（防止蓄纱过多）、床间切换方向一致性（同行不能同时存在前后相反的床间移针）以及局部张力过渡平滑性。这些约束嵌入在动作网格生成的多个阶段，并通过自修复机制协同处理。

### 2.4 程序化图案生成与结构化表示

程序化内容生成（PCG）领域已有大量基于规则、语法和参数化的图案生成方法。在计算机图形学中，shape grammar 和 L-system 被用于生成建筑、植物和装饰性图案，通过递归规则和参数化控制产生多样化的结构变体。在纺织领域，相关方法包括基于组织图的参数化针织图案设计、基于 grammar 的纹样生成和基于 layout planning 的图案布局。这些方法能够保证生成结果的结构一致性，但通常缺乏语义输入能力，难以从自然语言设计描述自动产生图案。

本文的 PatternPlan 与程序化方法的共同点在于采用结构化中间表示来降低生成难度，区别在于：PatternPlan 不仅描述视觉外观（形状、纹理、位置），还包含针织工艺语义（动作类型、针床属性、张力等级、弹性与稳定性），并支持父子层级约束和可编辑性。这一设计使得 PatternPlan 能够在保持视觉目标的同时，为后续动作网格编译提供工艺可行的结构约束。

### 2.5 Neural Inverse Knitting 与数据基础

Neural Inverse Knitting 将针织样片图像到动作指令的逆向映射作为研究任务，提出了从单张图像生成机台织造指令的逆向设计方法。该工作构建了包含图像、动作指令和色块编码的数据集，为后续针织生成研究提供了重要基础。本文的视觉预览训练数据来自该工作公开数据的一部分。原始数据包含 17 色动作空间，本文删除 2 个在当前系统中未使用且出现频率极低的色块（编号 15、16，分别对应特殊变体动作），形成十五色动作空间。删除后，15 色空间已覆盖当前系统支持的所有内部动作类型。数据集经过重复样本删除后，最终用于训练的样本来自 7 个针织样片类别。

与 Neural Inverse Knitting 不同，本文任务不是从已有针织图像反推动作指令，而是从自然语言设计语义生成新的组织色码图。Neural Inverse Knitting 的输出是机台可执行指令，本文的输出是内部动作色码图（尚未转换为完整机台指令），但可作为后续指令生成的输入。因此，本文更强调语义解析、层次化结构规划、工艺约束生成和视觉预览验证的完整链路。

### 2.6 条件图像生成与流匹配

条件图像生成旨在根据给定条件（如类别标签、边缘图、语义分割或文本描述）生成目标图像。主流方法包括条件 GAN、条件 VAE 和条件扩散模型。扩散模型通过逐步去噪过程学习数据分布，在图像生成质量上取得显著进展，但其采样过程通常需要数十到数百步迭代，计算开销较大。

条件流匹配（Conditional Flow Matching, CFM）是一种基于常微分方程的生成建模框架，通过插值路径连接噪声分布与目标分布，学习速度场以完成采样。相比扩散模型，流匹配具有更直接的训练目标（回归确定性流的速度场而非预测噪声）和更灵活的求解器选择（支持 Euler、midpoint 和 RK4 等数值积分方法）。TorchCFM 库提供了统一的实现框架，支持多种流匹配变体。本文第二阶段采用 CFM 作为生成框架，利用其在较少采样步数下仍能保持较好生成质量的特点，在推理效率和图像质量之间取得平衡。本文的模型架构基于 guided-diffusion 的 UNet 设计，并结合邻居感知条件编码器（NeighborAwareConditioner），将中心动作、邻域动作和物理工艺特征融合为条件信号。

### 2.7 大语言模型语义解析与结构化输出

大语言模型已被广泛用于语义解析任务，即将自然语言转换为计算机可处理的结构化表示。在知识库问答领域，LLM 被用于将自然语言问题转换为 SPARQL 或 Cypher 查询；在程序合成领域，LLM 能够根据自然语言描述生成可执行代码。然而，研究表明 LLM 的结构化输出仍存在格式不稳定、字段缺失和语义漂移等问题。“We Need Structured Output”等工作指出，通过格式约束和下游校验能够显著提升 LLM 输出的可靠性。

在纺织和制造领域，LLM 已被用于从文本生成织造指令参数和花型配置，但直接端到端输出的质量有限。本文采用分层策略：将大语言模型 API 限定为自然语言接口层，其作用是从用户描述中抽取形状、纹理、位置、层级和参数等候选字段；真正决定组织结果的是 PatternPlan schema、十五色动作空间、工艺约束和后处理修复。这种设计既利用了 LLM 的语义理解能力，又通过显式结构和规则系统保证了生成结果的工艺合法性。

## 3 方法

### 3.1 问题定义与动作空间

给定自然语言设计描述 D，本文目标是生成内部组织色码图 P 和结构感知视觉预览图 S：

$$
D \rightarrow P \rightarrow S
$$

其中，P 表示内部十五色动作图，用于组织生成、规则校验与第二阶段视觉预览；S 表示结构感知视觉预览结果，用于观察组织图在视觉层面的呈现形式。本文所定义的有效输出需同时满足语义一致性、工艺合法性与视觉可解释性。

#### 十五色针织动作空间

本文采用十五色动作空间作为基础表示，而非普通 RGB 调色板。动作编号、内部颜色与工艺属性统一定义于动作表中。每个动作由动作缩写、针织语义类别、针床或偏移属性、内部颜色、张力等级、弹性等级与稳定性等级共同描述。

表 1 列出了本文采用的十五个动作。张力等级取值为 1-7，数值越高表示相邻动作切换或局部负载风险越高；弹性与稳定性等级取值为 1-5，分别表征蓄纱/松弛倾向与作为支撑结构的稳定程度。需要指出的是，这三类属性并非来自实测传感器数据，而是结合公开针织工艺资料、Neural Inverse Knitting 指令语义以及本系统在生成、校验与视觉预览过程中的多轮调试经验建立的工程分级。在本文中，它们作为规则排序、风险评估与物理特征编码的启发式先验，后续仍需通过真实织造样片进一步标定。

**表 2 十五色动作空间的语义标注集**

| 语义类别 | 动作缩写 | 成圈 | 需下方支撑 | 提供上方支撑 | 特殊约束 | 工艺功能角色 |
| --- | --- | --- | --- | --- | --- | --- |
| LOOP | f_knit, b_knit | 是 | 是 | 是 | — | 主体支撑，构成织物基础结构 |
| TUCK | f_tuck, b_tuck, f_tuck_2, b_tuck_2 | 是 | 是 | 是 | 垂直堆叠≤3行 | 蓄纱凸起，用于波浪/蜂巢/浮雕纹理 |
| TRANSFER | xfer_f_b, xfer_b_f, xfer_l1, xfer_r1 | 否 | 是 | 是 | 横向偏移≤2针 | 针床切换、绞花位移与孔眼生成 |

| EMPTY | miss | 否 | 否 | 否 | — | 安全背景与逻辑空位 |
| DROP | carrier | 否 | 否 | 否 | 上方须清空 | 消除支撑、落布与收针 |

表中各属性的含义如下。

**成圈**（creates_loop）：该动作是否在当前针位形成新线圈。成圈动作为后续行提供编织基础，非成圈动作（移针、空针、落布）不形成新线圈。

**需下方支撑**（requires_support_below）：该动作是否要求正下方存在有效支撑（成圈或集圈）。成圈、集圈和移针均依赖已有线圈作为操作对象；空针和落布不依赖下方支撑。约束 H2（下方支撑检查）依据此属性判断动作合法性。

**提供上方支撑**（supports_above）：该动作是否为正上方的后续动作提供编织基础。成圈、集圈、移针和劈针均可作为上方动作的支撑；空针、落布和载体动作不提供支撑。

**特殊约束**：部分语义类别具有额外的结构限制。TUCK 类动作连续垂直堆叠不得超过 3 行，否则蓄纱过多导致张力风险（约束 H5）；TRANSFER 类动作的横向偏移不得超过 2 针（约束 H3）；DROP 类动作要求上方区域清空（约束 H7）。

该标注集将十五类离散动作映射为可查询的工艺语义属性，使约束检查器能够以统一接口判断动作合法性，而无需为每对动作组合编写专用规则。同时，该表也为张力评分提供属性来源：相邻动作的张力等级差值由表 1 中的张力列计算，而合法性判断则由本表中的支撑关系和特殊约束列共同决定。

### 3.3 语义解析与层次化结构计划

系统首先将自然语言输入解析为 PatternPlan。实现上，本文使用大语言模型 API 作为自然语言接口，将开放式描述转换为受限字段集合；随后系统对字段进行 schema 校验、层级关系补全、区域归一化与工艺可行性筛选。该设计使大模型承担基础语义识别工作，而结构规划、动作生成和约束修复仍由确定性规则与针织工艺知识主导。

PatternPlan 由多个 motif 组成，每个 motif 表示一个结构单元：

$$
m_i=(id_i,type_i,effect_i,role_i,region_i,params_i,parent_i)
$$

其中各字段的取值范围如下：

- **motif_type**（形状）：当前实现支持 circle、diamond、rectangle、hexagon、triangle、polygon、frame、wave、mesh、allover；schema 预留 heart、star、chevron、zigzag、cross、stripe、column、panel 等扩展类型，待后续实现
- **effect**（纹理效果）：当前实现支持 plain、reverse、wave_tuck、honeycomb、lace、rib；schema 预留 cable、relief、seed、links 等扩展类型
- **role**（结构角色）：center、border、allover、side_band、ground
- **region**（位置与尺寸）：包含 center（中心坐标）、size（尺寸）、shape（形状）等字段，或 type="full" 表示全画布填充
- **params**（工艺参数）：包含 period_x、period_y（纹理周期）、border_thickness（边框厚度）、split_col_offset、tuck_col_offset（事件偏移）等
- **parent_id**（父级区域）：指向另一个 motif 的 ID，表示当前区域被约束于父级区域内部

该表示使自然语言中的层级关系显式化。例如，“矩形外框包裹圆形，圆形内部填充波浪吊目”可被拆解为矩形边框、中心圆形与波浪纹理三个 motif，其中波浪纹理的 `parent` 指向圆形区域。在动作生成阶段，波浪事件需被约束于圆形内部。表 1a 给出一个典型的 PatternPlan JSON 示例（见下文）。

```json
{
  "layout_type": "framed",
  "motifs": [
    {
      "id": "m0",
      "motif_type": "rectangle",
      "role": "border",
      "effect": "rib",
      "region": {"center": [20, 20], "size": [32, 32]},
      "params": {"border_thickness": 2},
      "parent_id": null
    },
    {
      "id": "m1",
      "motif_type": "circle",
      "role": "center",
      "effect": "wave_tuck",
      "region": {"center": [20, 20], "size": [18, 18]},
      "params": {"period_x": 4, "period_y": 4},
      "parent_id": "m0"
    }
  ]
}
```

### 3.4 从结构计划到动作色码图

本节概述从 PatternPlan 到最终动作色码图的编译过程，包括视觉目标生成、稀疏事件规划和动作网格构建三个步骤。

PatternPlan 被渲染为 VisualSpec 后，系统进一步将其映射为 RealizationPlan。VisualSpec 描述目标视觉外观，RealizationPlan 则描述该外观由哪些针织动作实现。一个区域的 RealizationPlan 通常包含底布、边界、事件模式与事件参数：

$$
g:(shape,effect,role,placement,params)\rightarrow(base,border,event,\theta)
$$

表 3 给出典型语义与工艺实现关系。

| 视觉语义 | 工艺实现 | 事件模式 | 关键约束 |
| --- | --- | --- | --- |
| 波浪吊目 | 前床底布 + split/tuck 组合 | diagonal_wave | 成组出现，边界放不下时整组取消 |
| 蜂巢纹理 | 前后集圈交替 | honeycomb_tuck | 集圈间距、连续堆叠上限 |
| 稀疏网眼 | 底布 + 空针/移针局部事件 | mesh_miss | 孔洞密度、邻近隔离 |
| 菱形/六边形 | 几何 mask + 边界动作 | shape_border | 居中、对称、闭合 |
| 矩形边框 | 后床或罗纹边界 | frame | 连续闭合，不能被内部结构顶破 |
| 绞花/位移 | 左右移针组合 | diamond_side_xfer / cable | 左右负载平衡、目标不冲突 |

对于尚未稳定支持的组合，系统采用保守降级策略，即优先保留轮廓与稳定底布，不生成孤立特殊动作。此举旨在避免视觉上近似某种纹理但缺乏工艺意义的局部色块进入最终结果。

#### 稀疏事件规划

EventPoint 是工艺实现方案到低层动作网格的中间表示。系统并不直接预测 40 x 40 画布中的每个动作，而是根据区域 mask、纹理周期与工艺模式生成稀疏事件点：

$$
E={e_k=(r_k,c_k,a_k,z_k)\mid (r_k,c_k)\in \Omega(z_k),a_k\in A}
$$

其中 r 和 c 为事件坐标，a 为动作，z 为区域编号。对于带父级关系的区域，实际有效区域为：

$$
\Omega'(z)=\Omega(z)\cap \Omega(parent(z))
$$

该机制保证内部纹理不会溢出父级轮廓。例如，当波浪吊目位于圆形内部时，所有 `split` 与 `tuck` 事件均需同时满足波浪区域 mask 与圆形父级 mask。

#### 动作网格构建

ActionGrid 是最终的 40 x 40 动作编号矩阵。构建过程依次完成底布填充、边界绘制、稀疏事件写入，并通过 refinement、aesthetic pass、layer clipping、compiler guard 与规则修复进行稳定化。算法 1 概括了第一阶段流程。

```text
算法 1：语义驱动组织色码图生成
输入：自然语言描述 D
输出：内部色码图 P，统计报告 Q

1. 解析 D，得到层次化结构计划 PatternPlan
2. 将 PatternPlan 渲染为 VisualSpec
3. 将 VisualSpec 映射为 RealizationPlan
4. 根据 event_pattern 生成稀疏事件 EventPoint
5. 初始化 40 x 40 ActionGrid，并填充区域底布
6. 根据 border_style 绘制边界
7. 写入稀疏事件并执行局部过渡求解
8. 执行 refinement、aesthetic pass 和层级裁剪
9. 执行 compiler guard、画布边界安全化和成组组织完整性检查
10. 检查硬性约束、工艺约束和张力评分，并执行保守自修复
11. 导出内部色码图、视觉预览输入图和统计报告
```

### 3.5 工艺约束与自修复机制

本节整合动作合法性约束、工艺启发式约束与成组组织完整性检查，构成自修复的核心规则体系。

动作合法性约束用于过滤会导致动作不合法或结构无法形成的问题。本文实现的合法性约束包括 H1-H8。

| 编号 | 约束名称 | 检查对象 | 违反含义 | 修复策略 |
| --- | --- | --- | --- | --- |
| H1 | 非法动作索引 | 动作编号 | 编号不在十五色动作空间内 | 降级为前床成圈 |
| H2 | 下方支撑 | 成圈/集圈/移针/劈针 | 需要支撑的动作下方为空 | 补支撑或降级为空针 |
| H3 | 移针偏移上限 | 移针 | 横向偏移超过允许范围 | 改为劈针或更小位移 |
| H4 | 移针目标越界 | 移针 | 目标列超出画布 | 改为劈针 |
| H5 | 同行目标冲突 | 移针 | 多个来源落到同一目标 | 删除或降级冲突动作 |
| H6 | 集圈连续堆叠 | 集圈 | 同列连续集圈超过上限 | 插入成圈打断 |
| H7 | 落布上方清空 | 落布 | 落布上方仍有支撑结构 | 清空或替换为安全背景 |
| H8 | 同行床间方向冲突 | 床间移针 | 同行同时存在前后相反方向床间移针 | 改为劈针变体 |

这些约束体现了动作网格与一般图像的根本差异：一般图像允许任意颜色相邻，而组织色码图必须满足线圈支撑关系与动作组合关系。

#### 工艺启发式约束与张力评分

工艺启发式约束用于评估织物质量风险。它们不必然导致结构失败，但会影响稳定性、外观以及后续人工调整成本。本文实现的启发式约束包括 C1-C6。

| 编号 | 约束名称 | 工艺含义 |
| --- | --- | --- |
| C1 | 前后床成圈连续切换缺少过渡 | 同列 front/back loop 直接切换容易造成结构突变，需要 split 或 transfer 过渡 |
| C2 | 左右移针负载不平衡 | 绞花或位移组织左右负载差异过大，可能造成局部张力不均 |
| C3 | 床间移针行缺少支撑 | 含床间移针的行需要 tuck/miss/b_knit 等结构缓冲 |
| C4 | 特殊区域缺少边框 | cable/tuck 等区域外围需要结构边界提高稳定性 |
| C5 | 镂空区域未隔离 | 相邻 void 容易造成孔洞连通和支撑缺失 |
| C6 | tuck 与 cable 直接相邻 | 高蓄纱和高位移动作相邻会提高局部风险 |

系统同时计算张力评分：

$$
T(A)=\frac{1}{|N|}\sum_{(p,q)\in N}|t(A_p)-t(A_q)|
$$

其中 A_p 和 A_q 为相邻动作，t 表示动作张力等级。该指标用于衡量局部动作切换强度，可用于比较不同生成结果或消融设置下的相对风险。需要强调的是，张力评分是基于本文定义的动作属性分级计算的相邻动作切换强度指标，其与真实织造稳定性的关系仍需样片验证。它不能代表整体工艺风险，例如 C1 违例（前后床成圈连续切换缺少过渡）代表另一类结构风险，与张力评分相互独立。

#### 成组组织完整性

部分针织效果并非由单一动作构成，而是由多个动作组合实现。例如，波浪吊目通常由 `split` 与 `tuck` 按固定相对位置组成。系统在事件规划与最终输出前均检查组合完整性：

$$
c_{tuck}=c_{split}+\Delta
$$

若 `split` 或 `tuck` 任一侧因边界、mask 或修复而被删除，则另一侧同步删除，以避免最终色码图中出现孤立半组波浪。蜂巢与网眼等纹理亦采用类似的周期、密度与邻域检查。

### 3.6 内部色码输出

动作网格 A 通过内部十五色调色板 C_in 导出为组织色码图 P：

$$
P=C_{in}(A)
$$

该色码图保持与 Neural Inverse Knitting 数据色块体系一致的动作颜色语义，用于规则统计、第二阶段视觉预览输入与实验可视化。本文的重点在于动作语义生成、工艺约束控制与视觉预览验证。

### 3.7 结构感知视觉预览

本节描述第二阶段的模型架构、训练策略与损失设计。

第二阶段的目标是将内部十五色动作图转换为针织效果图，以评估第一阶段结果在视觉层面的结构表现。规则检查能够发现显式动作错误，但难以完全反映织物表面效果。例如，边框是否视觉闭合、波浪纹理是否连续、背景网眼是否稀疏等问题，均需要通过视觉预览结果进行进一步验证。需要说明的是，本文的第二阶段是条件图像生成任务，而非物理力学仿真；其输出可用于设计迭代和视觉检查，但不能替代真实织造验证。

![第二阶段结构感知仿真模块](E:/DeskTop/knitting_pattern_generator/docs/figures/stage2_simulation.svg)

图 2 展示了第二阶段结构感知视觉预览模块。该模块以内部十五色动作图为条件输入，通过邻域动作与物理工艺特征生成针织效果图。

#### 视觉预览模型架构

第二阶段采用基于 UNet 的条件生成模型。UNet 基于 guided-diffusion 架构，包含 3 个残差块，通道数配置为 128（Stage 1 为 64），通道倍率为 (1, 2, 2)，在分辨率 8 和 4 处引入 self-attention，使用 4 个 attention head，head 通道为 32，dropout 为 0.1。

条件编码采用邻居感知条件编码器（NeighborAwareConditioner）。该编码器首先将中心动作 ID 和 8 个邻居动作 ID 分别通过独立的 embedding 层映射为 256 维向量，然后对 8 个邻居特征加入位置编码后执行 multi-head self-attention（8 头，embed_dim=256），再通过 cross-attention 使中心特征查询邻居上下文，最后融合中心特征与邻居聚合特征得到条件向量。

对于 Stage 3 和 Stage 4，模型进一步引入物理特征编码器，将每个动作的 tension、elasticity 和 stability 三个属性归一化后通过 MLP 映射为与 embed_dim 相同的维度，并加到条件向量上。

#### 条件流匹配框架

第二阶段采用条件流匹配框架学习从噪声 patch 到目标针织 patch 的速度场。设 x0 为噪声，x1 为真实 patch，t 为时间，c 为条件向量，模型学习：

$$
v_\theta(x_t,t,c)\approx u_t
$$

训练损失为：

$$
\mathcal{L}_{flow}=\mathbb{E}\|v_\theta(x_t,t,c)-u_t\|_2^2
$$

推理阶段通过 ODE 积分得到目标 patch。系统支持 Euler、midpoint 与 RK4，其中默认采用 midpoint 以兼顾质量与效率。

#### Stage 1 到 Stage 4 的递进与训练配置

第二阶段训练分为四个 stage，其逐级引入的条件信息如下。

| 阶段 | 条件信息 | 模型特征 | patch_size | batch_size | epochs | lr | 验证目的 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Stage 1 | 中心动作 ID | 基础条件 UNet（class_cond） | 16 | 256 | 120 | 2e-4 | 建立动作到 patch 的基本映射 |
| Stage 2 | 3×3 邻域动作 | 邻居感知 self-attention 与 cross-attention | 16 | 256 | 120 | 2e-4 | 改善边界和上下文一致性 |
| Stage 3 | 邻域 + 物理特征 | tension / elasticity / stability 编码 | 16 | 256 | 80 | 1e-4 | 引入工艺属性先验 |
| Stage 4 | 物理特征 + 自适应随机插值 | 边界噪声、结构损失、纹理损失 | 8 | 128 | 30 | 3e-6 | 提升全图连续性和纹理表现 |

Stage 1 和 Stage 2 使用相同的训练配置，区别在于 Stage 2 将 class_cond 替换为邻居感知条件编码器。Stage 3 继承 Stage 2 的预训练权重，引入物理特征编码器。Stage 4 采用更小的 patch_size=8 以捕捉更精细的纹理细节，并采用更小的 batch_size 和学习率。

Stage 4 根据邻域动作差异构造边界图 B，并对区域内部与边界使用不同噪声强度：

$$
\sigma_{ij}=(1-B_{ij})\sigma_{inner}+B_{ij}\sigma_{boundary}
$$

本文配置中 `sigma_inner` 为 0.004，`sigma_boundary` 为 0.040，边界带宽为 2。该设置提高了模型在边界区域的鲁棒性，同时避免内部纹理受到过度扰动。所有 stage 均使用 AdamW 优化器，warmup 阶段分别为 8、8、5 和 2 个 epoch。训练在 NVIDIA GPU 上完成，Stage 1–3 采用单卡训练，Stage 4 采用 DDP 双卡并行训练。数据增强采用三层采样策略（three_tier），对低频动作类别进行加权采样以缓解类别不平衡。

#### 结构感知复合损失

Stage 4 使用复合损失：

$$
\mathcal{L}=
\lambda_m\mathcal{L}_{flow}
+\lambda_1\mathcal{L}_{1}
+\lambda_g\mathcal{L}_{grad}
+\lambda_f\mathcal{L}_{fft}
+\lambda_p\mathcal{L}_{physics}
+\lambda_b\mathcal{L}_{boundary}
+\lambda_s\mathcal{L}_{structure}
+\lambda_t\mathcal{L}_{texture}
$$

其中，梯度损失用于减少模糊，频域损失用于保持周期纹理，物理损失用于强化动作属性响应，边界损失用于约束区域交界，结构损失用于保留方向性与低频形态，纹理损失用于增强波浪、蜂巢、网眼等细节。

## 4 实验与结果分析

本章围绕本文的三个核心创新展开验证：语义输入是否能够稳定生成层次化结构计划，约束控制是否能够抑制工艺风险，第二阶段视觉预览是否能够对组织结果提供可视化验证。除固定语义案例外，实验进一步加入随机生成与基于原始 PatternPlan 的增量修改，以考察系统在开放输入和局部编辑场景下的稳定性。所有实验均在项目根目录执行，输出统一保存在 `outputs/runs/<run-name>`。第一阶段参数包括画布大小、纹理周期、repair/refinement/aesthetic 开关等；第二阶段视觉预览参数采用 `stage=4`、`num_steps=50` 与 `midpoint` 求解器。消融实验仅改变对应模块开关。第二阶段评估采用 50 张独立验证图，均来自与训练集不同的原始样片，避免训练/验证泄漏。

### 4.3 约束控制与自修复消融

本实验采用约束压力测试输入“矩形边框包裹中心圆形，圆形内部为波浪吊目，背景为平针”，比较完整系统与三种消融版本。该输入同时包含边框约束、圆形区域、波浪纹理和多主体布局，能够放大局部纹理事件、张力变化和边界保守化之间的差异。实验仅改变模块开关：无自修复版本关闭 repair，无 refinement 版本关闭局部编译细化，无 aesthetic 版本关闭美学后处理。

为避免仅凭视觉结果评价消融差异，本文定义四类约束评价指标。设 \(V_h\) 与 \(V_c\) 分别为硬性违例数和工艺软违例数，\(N_t\) 为纹理事件数，\(N_o\) 为父级区域外溢纹理数，\(N_u\) 为被判定为不完整组合的波浪/蜂巢单元数，\(T\) 为张力评分。硬性合法率定义为：

$$
Q_h=1-\frac{V_h}{HW+\epsilon}
$$

纹理外溢率定义为：

$$
E_o=\frac{N_o}{N_t+\epsilon}
$$

成组组织完整性定义为：

$$
Q_p=1-\frac{N_u}{N_t+\epsilon}
$$

为衡量在保持合法性的同时是否过度堆叠特殊动作，本文进一步定义约束质量评分：

$$
S_q=\alpha Q_h+\beta(1-E_o)+\gamma Q_p-\delta T-\eta\left|\frac{N_t}{HW}-\rho\right|
$$

其中 \(H=W=40\)，\(\rho\) 表示期望纹理事件密度，\(\epsilon\) 为防止分母为零的极小常数。本文实验中取 \(\alpha=0.4, \beta=0.2, \gamma=0.2, \delta=0.1, \eta=0.1\)，各权重根据经验设定，后续可通过参数敏感性实验进一步调整。该评分并非用于替代真实织造评价，而是用于比较不同模块开关下的相对风险。在当前实验中，full、no_repair、no_refine 和 no_aesthetic 的 \(Q_h\) 均为 1（无硬性违例），\(E_o\) 均为 0，因此 \(S_q\) 的差异主要来自纹理密度和张力评分。

| 设置 | Run name | Total events | Texture events | Hard 违例数 | Craft 违例数 | 外溢纹理数 | 不完整组合数 | 张力评分 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| full | ablation_full | 16 | 16 | 0 | 0 | 0 | 0 | 0.0308 |
| no repair | ablation_no_repair | 56 | 54 | 0 | 0 | 0 | 0 | 0.1038 |
| no refinement | ablation_no_refine | 48 | 28 | 0 | 0 | 0 | 0 | 0.0500 |
| no aesthetic | ablation_no_aesthetic | 48 | 36 | 0 | 0 | 0 | 0 | 0.0654 |

### 4.10 基线对比与后续计划

**基线对比**

为验证本文方法各模块的必要性，本节与两种基线方法进行定量对比。

**基线 1：Ours w/o PatternPlan。** 保持系统其余部分不变，但跳过 PatternPlan 层次化结构计划。LLM 输出的 VisualSpec 直接转换为扁平 PatternPlan（无父子层级、无 refinement 标志），后续流程与完整系统相同。该基线用于验证层次化结构计划的贡献。

**基线 2：LLM-Direct。** 要求大语言模型直接输出 40×40 的十五色动作网格（1600 个整数），不经过任何中间表示、规则编译或约束检查。该基线用于验证规则编译与约束机制的必要性。

实验采用 5 条测试输入，覆盖圆形+波浪、圆形+蜂巢、菱形+蜂巢、六边形+波浪等组合。评估指标包括：硬约束违例数（H1–H8）、软约束违例数（C1–C6）、张力评分、动作多样性（使用的动作类别数）、语义保真度（是否包含期望纹理动作）和推理时间。

表 6 基线对比结果（5 条测试输入的平均值）。

| 方法 | 生成成功率 | 硬约束违例↓ | 软约束违例↓ | 张力评分↓ | 动作多样性 | 语义保真度↑ | 推理时间(s)↓ |
|------|----------|----------|----------|----------|----------|----------|----------|
| Ours (完整系统) | 5/5 (100%) | 0 | 0.2 | 0.110 | 3.6 | 0.80 | 3.59 |
| Ours w/o PatternPlan | 5/5 (100%) | 0 | 0 | 0.101 | 3.6 | 0.80 | 2.87 |
| LLM-Direct | 0/5 (0%) | 0 | 0 | 0.0 | 1.0 | 0.0 | 198.2 |

结果显示，LLM-Direct 基线在所有 5 条测试输入上均退化为全空针背景（动作 5），未能生成任何有效纹理或边框结构，语义保真度为 0，推理时间高达平均 198.2 秒（主要消耗在输出 1600 个整数 token）。这一结果表明，大语言模型无法直接理解十五色动作空间的工艺语义并生成合法的 40×40 动作网格，验证了规则编译与约束机制的必要性。

Ours 与 Ours w/o PatternPlan 在当前测试集上的表现较为接近。完整系统在 test_04（菱形+蜂巢）上出现 1 项软约束违例，张力评分平均为 0.110；w/o PatternPlan 无软约束违例，张力评分平均为 0.101，推理时间略快（2.87s vs 3.59s）。这一现象的可能原因是：当前测试输入均为单 motif 简单结构，PatternPlan 的层次化优势（父子层级、多区域协调）尚未充分体现。对于包含多个嵌套 motif、复杂边框与多纹理叠加的输入，PatternPlan 的预期贡献将更加显著。

**后续评估计划**

为进一步提升论文的可靠性，后续计划补充以下两项评估：

**语义解析准确率评估。** 计划构建 100–500 条标注测试集，覆盖不同形状、纹理、层级和布局组合。对每条输入人工标注正确的 motif_type、effect、role、region 和 parent_id，然后与系统输出对比，报告字段级 Precision / Recall / F1 和完整解析成功率。

**用户评估。** 计划邀请多名评估者（至少 5 名，包括针织工艺专家和普通用户两类）对生成结果进行盲评，评估维度包括视觉质量（1–5 分）、纹理辨识度（1–5 分）、结构合理性（1–5 分）和偏好排序（A/B 测试）。报告评估者间一致性指标（Kendall's W 或 Fleiss' κ）。

## 5 真实织造验证

> **[待补充]** 本章预留用于真实横机织造样片验证。后续工作将把系统生成的动作色码图导入商业横机 CAD（如 Stoll M1 或 Shima Seiki SDS-ONE APEX），织造物理样片，并与视觉预览结果进行对比分析。评估维度包括：
> - 视觉预览图与真实样片的外观一致性（颜色分布、纹理连续性、边界闭合度）
> - 动作色码图在实际织造中的可执行性（是否存在机台报错、断纱、脱圈等异常）
> - 张力评分与真实织物手感/平整度的相关性
> - 典型成功案例与失败案例分析
